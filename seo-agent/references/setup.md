# Инициализация подключений

Команда скилла: `$seo-agent init`. В чате сначала предложи выбрать **Google Search Console**, **Яндекс Вебмастер** или **оба**. Затем помоги выбрать проект и указать пути к локальным файлам. Секреты в чате не запрашивай. Скрипт с выбором и скрытым вводом запускается пользователем в локальном терминале; не запускай интерактивный мастер внутри инструмента, если пользователь не сможет взаимодействовать с его stdin. Для Google согласие в браузере всегда даёт пользователь.

## Команды

Для Google один раз установи зависимости в виртуальное окружение проекта:

```sh
python3 -m venv <project>/.venv
<project>/.venv/bin/python -m pip install -r <skill>/requirements.txt
```

Добавь `.venv/` в `.gitignore` при создании окружения. Для настройки только Яндекса достаточно Python 3 без пакетов.

```sh
<project>/.venv/bin/python <skill>/scripts/setup.py init --project <project>
```

Мастер предлагает провайдера и список сайтов. Для прямого выбора:

```sh
<project>/.venv/bin/python <skill>/scripts/setup.py init --project <project> --provider google --google-client <path-to-downloaded-oauth.json>
python3 <skill>/scripts/setup.py init --project <project> --provider yandex
python3 <skill>/scripts/setup.py status --project <project>
```

`--provider both` подключает оба сервиса. `--google-property 'sc-domain:example.com'` или точный URL и `--yandex-property 'https://example.com/'` позволяют выбрать ресурс без вопроса в терминале. Ничего автоматически не выбирай по похожести доменов: GSC domain property, URL-prefix и разные протоколы могут давать разные данные.

Повторный `init` использует сохранённый доступ и снова проверяет список сайтов. `--reauth` запускает новую авторизацию/ввод токена. Уже настроенные другие сервисы сохраняются; ошибка одного не удаляет успешное подключение второго. Ошибочный запуск возвращает ненулевой код, включая частичный успех `both`. `status` показывает сохранённые настройки и дату предыдущей проверки, но не выполняет сетевую проверку и не гарантирует действующий токен.

## Google Search Console

1. В Google Cloud включи **Search Console API**. Одного включения API недостаточно.
2. Настрой Google Auth Platform / OAuth consent screen. Если приложение External находится в Testing, добавь свой Google аккаунт в Test users. У тестовых приложений refresh token может иметь ограниченный срок; при отзыве или истечении повтори `init --reauth`.
3. Создай OAuth client типа **Desktop app**, скачай JSON и укажи его путь мастеру. Не отправляй содержимое файла в чат. Это не service-account JSON и не обычный API key.
4. Мастер откроет системный браузер и запросит только `https://www.googleapis.com/auth/webmasters.readonly`. Используются PKCE, проверка OAuth state библиотекой и callback на `127.0.0.1` со случайным портом. Код/токен не нужно копировать в чат или терминал. Заверши вход в течение 3 минут. Если браузер не открылся, повтори команду на локальном компьютере с системным браузером.
5. После авторизации мастер читает доступные ресурсы Search Console и предлагает выбрать сайт. Если список пуст, проверь Google аккаунт и добавление/подтверждение сайта в Search Console.

## Яндекс Вебмастер

1. Добавь и подтверди сайт в Вебмастере под нужным Яндекс ID.
2. Создай приложение в [Яндекс OAuth](https://oauth.yandex.ru/), выбери веб-сервисы и redirect URI `https://oauth.yandex.ru/verification_code`.
3. Для чтения данных выбери `webmaster:hostinfo`; не добавляй право управления подтверждением `webmaster:verify` ради анализа. Официальная общая инструкция описывает оба права для полного сценария Вебмастера, но мастер не выполняет операции подтверждения или изменения сайта.
4. Скопируй ClientID и открой локально в браузере `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`. Разреши доступ. Полученный OAuth токен введи **только в скрытый запрос локального терминала** либо запиши в `.env` как `YANDEX_WEBMASTER_TOKEN=...`.
5. Мастер проверяет пользователя и предлагает подтверждённые сайты из API. Wordstat Cloud API-ключ для этого не подходит. Токен Вебмастера может истечь или быть отозван — повтори настройку при ошибке авторизации.

## Хранение и безопасность

- Общая конфигурация и выбранные ресурсы: `<project>/.seo/connections.json`.
- Google refresh/access token и client config для обновления: `.seo/secrets/google-token.json`.
- Яндекс OAuth токен: `.seo/secrets/yandex-token.json`; исходный токен из `.env` имеет приоритет при следующей настройке.
- Каталоги `.seo` и `secrets` получают права `700`, записанные файлы `600`. Записи атомарные; symlink для файлов и каталогов хранения отклоняется. В проектный `.gitignore` добавляется `/.seo/`.
- Если секреты уже были закоммичены, `.gitignore` их не удалит из истории. Отозви такие ключи и устрани отслеживание отдельно. Скачанный исходный Google JSON храни вне Git; мастер не меняет его права и не удаляет его.
- Файлы локальные, без шифрования. Для их переноса требуется такое же аккуратное обращение, как с паролями. Не копируй секреты в память SEO, Canvas, отчёты или сообщения. В памяти допустимы только выбранный ресурс, имя провайдера и дата проверки.
- В API выполняются только чтение пользователя и списков сайтов. Авторизация Google может обновлять токен. Мастер не меняет сайты, права или настройки поисковых сервисов.

Инициализация подключает аккаунты и выбирает ресурсы; она не собирает поисковую статистику и не создаёт ежедневное расписание. Не утверждай обратное. Для исследования планируй отдельные клиенты выгрузки метрик, использующие эти credentials.
