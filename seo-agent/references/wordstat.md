# Поиск запросов через Wordstat

Интеграция использует официальный REST API Yandex Search API. Проверено по официальной документации 2026-10-31. Старый самостоятельный OAuth API Wordstat не используется.

## Подключение

Создай API-ключ сервисного аккаунта с ролью `search-api.webSearch.user` и областью действия `yc.search-api.execute`. Нужен доступ к каталогу и работающий биллинг Yandex Cloud. Запросы расходуют квоты и могут тарифицироваться по условиям аккаунта. Тарифы не зашиты в скилл.

### Как получить API-ключ

1. Войди с Яндекс ID в [Yandex Cloud](https://console.yandex.cloud/). Выбери облако и каталог для проекта; при первом использовании создай их и подключи платёжный аккаунт по подсказкам консоли. Проверь актуальные условия оплаты и квоты до сбора данных.
2. Открой [AI Studio](https://aistudio.yandex.cloud/) в нужном каталоге. Нажми **Создать API-ключ**, задай описание, например `seo-agent`, выбери срок действия и нажми **Создать**. Этот вариант создаёт сервисный аккаунт с преднастроенными правами. Если кнопка недоступна, попроси администратора каталога создать ключ: для этого пути нужна роль `resource-manager.admin`.
3. Сохрани **секретную часть ключа** в `YANDEX_API_KEY`. Идентификатор ключа не подходит для запросов. После закрытия окна секрет больше не показывается.
4. Проверь в **Доступ → Права доступа**, что у сервисного аккаунта есть `search-api.webSearch.user`. Ключ должен включать область `yc.search-api.execute`. Это независимые настройки: роль аккаунта не добавляет область в уже выпущенный ключ.
5. Для отдельного аккаунта только под SEO или ручного выбора области используй [консоль Cloud](https://console.yandex.cloud/): **Identity and Access Management → Сервисные аккаунты → нужный аккаунт → Создать новый ключ → Создать API-ключ**. Выбери `yc.search-api.execute` и срок действия; отдельно назначь аккаунту роль `search-api.webSearch.user` на рабочий каталог. Если аккаунта ещё нет, сначала создай его в этом разделе. Для выпуска ключа существующего аккаунта нужны права `iam.serviceAccounts.apiKeyAdmin` либо эквивалентные; для назначения ролей — права управления доступом каталога.
6. Скопируй **ID каталога**, не ID облака, аккаунта или ключа. В AI Studio наведи указатель на название каталога сверху и нажми значок копирования. Сохрани значение в `YANDEX_FOLDER_ID`.
7. Заполни локальный `.env`, затем выполни проверку настроек ниже. Для проверки реального доступа запусти один запрос с `--phrase 'тема вашего сайта' --limit 10 --max-requests 1 --output <project>/.seo/wordstat-check.json`. Это сетевой запрос с расходом квоты; успешная локальная проверка `--check-config` его не заменяет.

Если ключ создаётся для существующего сервисного аккаунта в AI Studio: **Доступ → API-ключи → меню нужного аккаунта → Создать API-ключ**. При истечении срока выпусти новый ключ и замени значение в `.env`.

Названия пунктов могут меняться: сверяйся с [официальной инструкцией получения ключа](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key) и [требованиями Wordstat](https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-gettop). Не используй старый OAuth токен Wordstat вместо Cloud API-ключа.

### Настройка проекта

В корне проекта создай `.env` по образцу `.env.example`:

```dotenv
YANDEX_API_KEY=your_service_account_api_key
YANDEX_FOLDER_ID=your_folder_id
```

Если скилл перенесён отдельно, создай эти две переменные вручную. Секрет не передавай в чат, аргументы команд, исследование или память. `.env` уже исключён из git в этом проекте; в другом проекте проверь его исключение перед сохранением ключа. Переменные окружения имеют приоритет над `.env`. Загрузчик поддерживает буквальные `KEY=value`, кавычки и `export`; не выполняет shell команды и подстановки. Не читай `.env` через инструменты с выводом содержимого. Наличие настроек проверяй так:

```sh
python3 <skill>/scripts/wordstat.py --env-file <project>/.env --check-config
```

Это проверяет наличие настроек, но не доступ к API. Дополнительные Python пакеты не требуются.

## Сбор запросов

После изучения сайта сформируй исходные фразы из продуктов, задач клиентов и существующих страниц. Начни с 5–10 релевантных фраз. Не своди подбор к словам, которые пользователь уже знает: расширь семантику через `results` и `associations`, отфильтруй чужие значения и при необходимости выбери новые исходные фразы.

```sh
python3 <skill>/scripts/wordstat.py --env-file <project>/.env --phrase 'утепление дома' --phrase 'теплопотери дома' --regions 225 --limit 100 --cache-dir <project>/.seo/wordstat-cache --output <project>/.seo/sites/<site>/research/wordstat.json
```

Проверяй ID региона через `--regions-tree` (отдельный API запрос); не подставляй регион пользователя вместо региона бизнеса. Без `--regions` статистика по всем регионам, что нужно явно отметить. Для большого набора используй `--phrases-file <seeds.txt>`: одна фраза в строке, комментарии начинаются с `#`. `--device` принимает `all`, `desktop`, `phone`, `tablet`.

По умолчанию максимум 20 сетевых запросов за запуск, последовательно с паузой, без автоматических повторов. Предел можно задать через `--max-requests` (1–100). Планируй бюджет на весь этап: новые запуски не обнуляют согласованный бюджет исследования. Кэш живёт 7 дней, ключ учитывает исходную фразу, регион, устройство, размер ответа и каталог. `--refresh` запрашивает свежие данные. При превышении бюджета уже полученные ответы остаются в кэше, но итоговый файл не перезаписывается; уменьши набор либо продолжи из кэша в рамках бюджета. Не запускай бесконечное расширение семантики.

Для повторных исследований используй новый файл с датой/ID запуска, не затирай источник, на который уже ссылается память. В итоговом JSON есть уникальные фразы, наблюдения с частотностями и исходными фразами, сырые ответы и параметры с датой получения. Ключ API никогда туда не записывается. Кэш может содержать ответы разных дат; проверяй `fetched_at` каждого наблюдения.

## От запросов к статьям

1. Сохрани ссылку на JSON и краткие выводы в `research` памяти через `memory.py`.
2. Отфильтруй нерелевантные фразы по смыслу бизнеса и рынку. Сохраняй коммерческие запросы отдельно от информационных, не обещая, что каждому запросу нужна статья.
3. Объедини близкие запросы в кластеры по интенту; проверь выдачу и существующие URL сайта. Wordstat не определяет интент, конкуренцию и возможность ранжирования автоматически.
4. Для каждого перспективного кластера предложи статью: заголовок, основной запрос, дополнительные вопросы, частотность и источник, целевой URL, отличие от существующего контента, связь с продуктом, приоритет и объяснение.
5. Частотность — число запросов за последние 30 дней на дату получения, с указанными фильтрами и операторами. Это не уникальные пользователи, не точная месячная частотность без операторов и не обещание кликов. Не суммируй пересекающиеся запросы в «потенциальный трафик». `totalCount` и частотность каждой строки имеют разный смысл. Ассоциации требуют отдельной смысловой проверки.
6. Добавь выбранные статьи в `tasks` со стабильными ID и ссылками на доказательства спроса. Не создавай вторую задачу для того же интента. Обнови план и первые ТЗ.

При 401/403 сообщи о проблеме доступа; при 429 останови сбор до восстановления квоты. Не обходи ошибки повторными циклами и не подставляй придуманные цифры. Если ключ не настроен, продолжай доступное исследование, помечая непроверенные темы как гипотезы.
