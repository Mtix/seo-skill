# SEO Skill

Комплект из трёх скиллов для контентного SEO: исследование сайта и запросов, план статей, подготовка понятных текстов и аудит с задачами исправлений. Память по каждому сайту сохраняется локально между чатами, использующими один проект.

Цель — привлекать потенциальных покупателей из поиска и проверять результат по данным. Скиллы не гарантируют позиции, посещения и продажи и не публикуют контент автоматически.

## Состав

- **[seo-agent](seo-agent/SKILL.md)** — основной сценарий: изучить сайт, собрать запросы, выбрать темы, составить план и вести очередь работ.
- **[seo-article](seo-article/SKILL.md)** — написать или улучшить статью под запрос и намерение читателя, проверить факты и подготовить редакторские заметки.
- **[seo-audit](seo-audit/SKILL.md)** — проверить доступные технические и контентные сигналы, сформировать задачи с доказательствами, приоритетами и критериями приёмки.

Это инструкции для агента и вспомогательные Python программы. Качество исследования и написание текста обеспечивает агент с доступными инструментами поиска и браузера; Python скрипты отвечают за память, API и настройку доступов. Отдельного автономного сервера или универсального crawler здесь нет.

## Что умеет

### Исследование и планирование

Агент изучает предложение сайта, аудиторию, язык и предполагаемый рынок; просматривает существующие страницы, robots.txt и sitemap. Затем сопоставляет запросы с намерениями пользователей и текущими URL.

Для кластера выбирается действие: создать страницу, обновить существующую, объединить материалы или отказаться от темы. Близкие запросы не превращаются автоматически в отдельные статьи. Коммерческому запросу может требоваться страница услуги, а не публикация в блоге.

Приоритет учитывает связь с бизнесом, подтверждение спроса, наблюдаемую конкуренцию, полезное отличие и трудозатраты. Оценка агента не выдаётся за измеренную сложность из SEO сервиса.

### Wordstat

Встроенный клиент официального Wordstat API в Yandex Search API получает популярные и похожие запросы. Поддерживаются несколько исходных фраз, регион, устройство, операторы и сохранение исходных ответов с датой и параметрами.

Кэш действует семь дней. По умолчанию ограничено число новых обращений за запуск, запросы отправляются последовательно. Автоматических повторов при ошибке нет. Расширение семантики выполняет агент в пределах выбранного бюджета.

`totalCount` исходного запроса и `results.count` отдельных строк — разные показатели. В запросах с операторами частотности строк не становятся точными автоматически. Пересекающиеся значения не суммируются в потенциальный трафик. Отсутствующий показатель не подменяется нулём.

### Статьи

Скилл готовит прямой ответ в начале, понятную структуру, конкретные примеры и естественное употребление запросов. Факты и возможности продукта проверяются; придуманные отзывы, опыт и статистика запрещены. Условные примеры обозначаются как условные.

Текст статьи и редакторские заметки сохраняются отдельно. В заметках остаются Title, description, предлагаемый URL, источники, вопросы и вердикт готовности. Нет обязательной плотности ключей и объёма текста ради SEO.

### Аудит

В зависимости от доступных инструментов проверяются ответы страниц, перенаправления, robots.txt, noindex, canonical, sitemap, метаданные, внутренние ссылки и содержимое. Отрисовка, мобильный вид и скорость проверяются только при наличии подходящих инструментов.

Каждая проблема получает URL или охват шаблона, доказательство, дату, последствия, приоритет, рекомендуемое исправление и критерий приёмки. Гипотезы отделяются от подтверждённых ошибок. Повторная проверка обновляет существующие задачи. Выборка страниц не называется полным аудитом, sitemap не считается доказательством индексации.

## Быстрый старт

Откройте проект в агенте, поддерживающем Agent Skills. Для поиска и исследования нужны доступные веб инструменты. Для вспомогательных программ нужен Python 3; для нового окружения рекомендуется актуальная поддерживаемая версия Python.

Скиллы подключаются через `.agents/skills/`. Если ваш инструмент не обнаружил их автоматически, явно укажите путь к нужному `SKILL.md`. Комплект нужно переносить целиком: дополнительные скиллы используют общую память основного.

В новом клоне при отсутствии проектных ссылок выполните из корня репозитория:

```sh
mkdir -p .agents/skills
ln -s ../../seo-agent .agents/skills/seo-agent
ln -s ../../seo-article .agents/skills/seo-article
ln -s ../../seo-audit .agents/skills/seo-audit
```

Эти команды рассчитаны на macOS/Linux и отсутствующие ссылки. Уже настроенные скиллы повторно подключать не нужно. В инструментах без автоматического обнаружения используйте явный путь.

Примеры запросов в чате:

```text
$seo-agent https://example.com
$seo-agent init
$seo-agent article SEO-013
$seo-agent audit https://example.com
$seo-article https://example.com что подарить брату на день рождения
$seo-audit https://example.com
```

Это сценарии обращения к агенту, а не команды оболочки. Можно также написать: «найди запросы», «обнови план», «что дальше», «проверь исправление» или «покажи статус».

## Настройка Wordstat

Для Wordstat нужен API-ключ сервисного аккаунта Yandex Cloud. `Client ID` и `Client Secret` приложения Яндекс OAuth не заменяют этот ключ.

1. Выберите каталог в Yandex Cloud и подключите платёжный аккаунт.
2. Создайте сервисный аккаунт и назначьте ему роль `search-api.webSearch.user` на рабочий каталог.
3. Выпустите API-ключ с областью `yc.search-api.execute`.
4. Создайте локальный `.env` по образцу [.env.example](.env.example), сохранив уже существующие настройки, если файл есть.

```dotenv
YANDEX_API_KEY=secret_part_of_service_account_api_key
YANDEX_FOLDER_ID=folder_id
```

В `YANDEX_API_KEY` нужна секретная часть, не идентификатор ключа. В `YANDEX_FOLDER_ID` нужен ID каталога, не облака, аккаунта или ключа. Значения вводятся локально; отправлять их в чат не нужно.

Из корня репозитория:

```sh
python3 seo-agent/scripts/wordstat.py --check-config
python3 seo-agent/scripts/wordstat.py --phrase 'песня в подарок' --regions 225 --limit 30 --max-requests 1 --output .seo/wordstat-check.json
```

Первая команда проверяет наличие конфигурации без сетевого запроса. Вторая выполняет одно обращение к API и расходует квоту; использование может тарифицироваться.

Дополнительно доступны `--env-file`, `--phrases-file`, `--device`, `--cache-dir`, `--refresh` и `--regions-tree`. Полный список — через `--help`.

Подробная [инструкция получения ключа и работы с Wordstat](seo-agent/references/wordstat.md). Актуальные цены проверяйте в [официальных правилах тарификации](https://aistudio.yandex.ru/ru/docs/search-api/pricing): тарифы не зашиты в программу.

## Google Search Console и Яндекс Вебмастер

Мастер настраивает доступ и выбор сайта. Для Google установите библиотеки в локальное окружение:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r seo-agent/requirements.txt
.venv/bin/python seo-agent/scripts/setup.py init
```

Запускайте интерактивную настройку в обычном локальном терминале, где пользователь может отвечать на вопросы. Google требует согласия пользователя в браузере.

Мастер предлагает Google, Яндекс Вебмастер или оба сервиса. Wordstat настраивается отдельно через `.env` по инструкции выше.

### Google

Включите Search Console API в Google Cloud, настройте OAuth consent screen и создайте OAuth client типа **Desktop app**. Скачанный JSON храните вне Git и укажите его путь мастеру. В режиме Testing при необходимости добавьте свой аккаунт в тестовые пользователи.

```sh
.venv/bin/python seo-agent/scripts/setup.py init --provider google --google-client /absolute/path/to/desktop-oauth.json
```

Запрашивается только `webmasters.readonly`. Используются PKCE и callback на `127.0.0.1` со случайным портом. После входа нужно выбрать ресурс из доступного списка. JSON сервисного аккаунта и обычный API key для этого сценария не подходят.

### Яндекс Вебмастер

Нужен отдельный OAuth токен с правом чтения `webmaster:hostinfo`, не Cloud API-ключ Wordstat. Токен можно записать в `.env` как `YANDEX_WEBMASTER_TOKEN` или ввести в скрытом поле локального терминала.

```sh
python3 seo-agent/scripts/setup.py init --provider yandex
python3 seo-agent/scripts/setup.py status
```

`--reauth` запускает повторную авторизацию. `status` показывает сохранённые настройки и дату предыдущей проверки, но не проверяет доступ в сети прямо сейчас.

Подробные шаги: [настройка подключений](seo-agent/references/setup.md).

**Граница реализации:** мастер авторизует аккаунты и читает список сайтов. Клиенты полноценной выгрузки поисковых показателей GSC/Вебмастера пока не реализованы. Для анализа статистики нужен экспорт или следующий этап разработки. Наличие настроек не означает, что метрики уже получены.

## Безопасность доступов

- Настоящие ключи, OAuth JSON и токены не нужно отправлять в чат.
- `.env`, `.env.*`, `.seo/` и `.venv/` исключены из Git; `.env.example` содержит только образец без секретов. В другом проекте проверьте исключения отдельно.
- Загрузчик `.env` не выполняет shell команды и подстановки. Переменные окружения имеют приоритет над файлом.
- Клиент Wordstat не добавляет ключ в отчёты и память и не выводит заголовок авторизации или сырой серверный ответ ошибки. Запросы идут по HTTPS на фиксированный API endpoint без перенаправлений.
- Мастер сохраняет файлы доступов с правами `600`, каталоги хранения — `700`; запись атомарная, symlink для файлов и каталогов хранения отклоняется.
- Для вручную созданного `.env` задайте права `600`. Скачанный исходный Google JSON храните отдельно: мастер его не удаляет и не меняет права.
- `.gitignore` не удаляет секрет, который уже попал в историю Git. Такой доступ нужно отозвать и отдельно устранить отслеживание.

Локальные файлы секретов **не зашифрованы**. Интеграции с Keychain или другим системным хранилищем пока нет. Права файлов ограничивают доступ других локальных пользователей, но не защищают от процессов, работающих от имени владельца.

## Память и результаты

По умолчанию все данные находятся в `<рабочий проект>/.seo/`:

```text
.seo/
  memory.sqlite3             Состояние сайтов и история изменений
  connections.json           Выбранные ресурсы и даты проверок
  secrets/                   Локальные credentials; не публиковать
  wordstat-cache/            Кэш ответов Wordstat
  sites/<site>/
    plan.md                  Текущий план
    research/                Источники и ответы API
    briefs/                  ТЗ и редакторские заметки
    drafts/                  Черновики
    audits/                  Проверки сайта и наблюдения
```

SQLite — источник истины по задачам. Markdown и JSON — связанные результаты исследования и работы. База хранит версии и снимки изменений; конфликт версий запрещает молча затереть новое состояние. Существующие задачи не удаляются: их можно отменить с причиной. Для `done` требуется подтверждение выполнения.

Память сохраняется между чатами, имеющими доступ к тому же проекту. Между компьютерами автоматически не синхронизируется. При переносе учитывайте, что некоторые ссылки на локальные результаты могут быть абсолютными и потребуют обновления. Не публикуйте всю `.seo/`: она содержит секреты и пользовательские данные.

Команды памяти из корня репозитория:

```sh
python3 seo-agent/scripts/memory.py --db .seo/memory.sqlite3 sites
python3 seo-agent/scripts/memory.py --db .seo/memory.sqlite3 init https://example.com
python3 seo-agent/scripts/memory.py --db .seo/memory.sqlite3 show example.com
python3 seo-agent/scripts/memory.py --db .seo/memory.sqlite3 history example.com
```

Формат записи и правила версий: [описание памяти](seo-agent/references/memory.md).

## Принципы оценки результата

Агент должен отделять факт от интерпретации и гипотезы, указывать источники и ограничения, сохранять причины смены решений. Слабые темы откладываются или отклоняются; обязательной квоты статей нет.

Публикация, индексация, рост показов, переходы и оплаты — разные события. Отсутствие данных не превращается в ноль; рост показов не называется ростом продаж. При малой выборке допустимый вывод — «недостаточно данных». Позиции и посещаемость не гарантируются.

## Практическая проверка

Комплект проверяли на SongGift: изучили сайт, сохранили инвентарь страниц, подключили Wordstat, пересмотрели предварительные темы после получения данных и подготовили пилот пяти статей о подарках брату, сестре, подруге, жене и другу.

Этот пример подтверждает работу процесса и получение данных API, но не рост органики: новые материалы в рамках этой работы ещё не опубликованы, результаты продвижения не измерены. Локальная история сайта находится в `.seo/` и намеренно не включается в общий репозиторий.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты покрывают память, конфликты версий, зависимости, подтверждение завершения, Wordstat запросы и кэш, обработку ошибок и параметры мастера доступов. Тесты Google требуют установленных зависимостей; без них соответствующие проверки пропускаются. Модульные проверки используют подменённые ответы и не доказывают доступ к вашим реальным аккаунтам.

## Текущие ограничения

- Нет ежедневного автоматического запуска и фонового сервера.
- Нет автоматической публикации в CMS и изменения сайта.
- Нет полного crawler и собственной системы измерения позиций.
- Нет готовой выгрузки поисковых метрик GSC/Вебмастера.
- Нет зашифрованного системного хранилища секретов.
- Качество исследования зависит от доступных инструментов и источников; отсутствие браузера, API или выгрузки должно быть обозначено в результате.

Установка скилла не предоставляет разрешение на публикацию, оплату сервисов, изменение сайта или прав доступа. Такие действия выполняются по соответствующему поручению пользователя.
