# Проверки сайта и границы выводов

## Доступность и индексирование

- Проверь ответы выбранных страниц, HTTP/HTTPS и важные перенаправления доступным инструментом. Зафиксируй статус и конечный URL. Один 403 инструменту может быть антибот защитой; он не доказывает недоступность сайта поисковику.
- Прочитай robots.txt с учётом конкретного User-agent. Запрет обхода не равен noindex. Чтобы прочитать noindex, робот должен иметь доступ к странице. Не рекомендуй закрыть robots.txt страницу, которую нужно убрать из поиска через noindex.
- Проверь meta robots и X-Robots-Tag, если заголовки доступны. Сопоставь с назначением страницы, не требуй индексации служебных разделов.
- Проверь canonical в HTML и HTTP заголовке, если доступны: корректность целевого URL, ответ, согласованность с назначением и внутренними ссылками. Canonical — сигнал, не гарантия выбора поисковика. Для объединения/смены URL нужна отдельная оценка последствий, не автоматическое удаление страницы.
- Для фактической индексации используй только доступный источник, который её подтверждает. Текущий мастер подключений сам не выгружает данные Search Console/Вебмастера: не считай настройку доступов полученным отчётом. Без клиента/экспорта пометь это как непроверенное.

## Sitemap и структура

- Проверь доступность и синтаксис доступного sitemap или индекса. Для большой карты проверяй ограниченную выборку URL и назови её. XML разбирай без внешних сущностей, с ограничением размера; если инструмент этого не обеспечивает, ограничься просмотром, а не небезопасным XML парсером.
- Ищи подтверждённые нецелевые URL в карте: редиректы, ошибки, явные noindex или canonical на другое место. Сначала выясни назначение. Отсутствие страницы в sitemap не доказывает, что её нельзя найти или проиндексировать.
- Проверь навигацию к ключевым услугам и статьям, смысл ссылок, найденные битые внутренние ссылки. «Страница сирота» требует инвентаря ссылок; по нескольким просмотрам можно говорить только «не найдена в проверенных путях».
- Не рекомендуй массово закрывать параметры, пагинацию или фасеты без проверки назначения и спроса. Проверяй доступность важных дочерних страниц.

## Контент и метаданные

- Сопоставь title, H1, вступление и реальную задачу страницы. Конкретизируй, что неверно/неясно и как исправить. Длина в символах сама по себе не подтверждает SEO ошибку.
- Отсутствие description — возможность улучшения, не доказательство потери ранжирования. Переписывание сниппета поисковиком ожидаемо.
- Дубли title/контента и пересечение интента подтверждай сравниваемыми URL и фрагментами. Пересечение тем не равно доказанной каннибализации трафика.
- Проверь актуальность фактов, наличие основного ответа, полезных примеров и соответствие продукту. Не назначай обязательный объём текста, плотность ключей, FAQ или единственный H1 как универсальную гарантию SEO.
- Изображения: содержательные alt там, где они нужны для понимания; для декоративных допустим пустой alt. Не заполняй alt ключевыми словами.

## Отрисовка, мобильные устройства, скорость

- Если браузер доступен, проверь видимость основного текста и ссылок после отрисовки. Без сравнения raw HTML и DOM не делай вывод «поисковик не видит JS».
- При проверке мобильного вида укажи viewport и конкретный дефект: перекрытие текста, недоступная кнопка, горизонтальный скролл. Это визуальная диагностика, не редизайн. Если отдельная задача требует дизайна, применяй соответствующий доступный скилл.
- Скорость оценивай только измеренным инструментом. Отделяй лабораторный замер от полевых Core Web Vitals; указывай URL, устройство, дату и условия. Один Lighthouse запуск не доказывает полевой статус CWV; отсутствие полевых данных не означает прохождение проверки.
- Структурированные данные проверяй при наличии основания для конкретного типа: соответствие видимому содержимому и актуальным правилам. Не обещай расширенный результат после добавления разметки.

## Критерий приёмки: пример

Наблюдение: на проверенной странице услуги в HTML найден `noindex`, хотя владелец подтвердил её публичное поисковое назначение.

Задача: убрать нежелательный noindex из шаблона этой услуги. Приёмка: страница отвечает 200, доступна для обхода нужному роботу, noindex отсутствует в HTML и доступных HTTP заголовках, canonical согласован с целевым URL. Индексация и трафик проверяются отдельной задачей позже. Если заголовки недоступны, приёмка остаётся частичной.
